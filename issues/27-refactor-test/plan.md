## Answers to the audit questions

### `fixtures/` vs `golden/`

The intended distinction is **inputs vs expected outputs**: `fixtures/` is data fed *into* the code,
`golden/` is recorded output *of* the code, regenerated and compared as a regression pin.

`fixtures/valid_nodes/` breaks it. Those three files are `coral register` **output** — the same kind
of artifact as `golden/`, on the wrong side of the fence. They are read by exactly one test
(`test_registry.py::test_existing_registry_files_valid`), which asserts only that committed JSON has
the keys someone gave it: it passes with `registry.py` completely broken and fails only if a human
hand-edits a fixture. `golden/` covers the same three plugin sets properly. → **D1**.

`fixtures/valid_workflows/` is genuine input, but it is *shared* input with no owner — which is the
defect [the separation principle](#the-separation-principle) removes. Every file in it is rehomed to
its owner (steps 4 and 5) and the directory disappears; so does `tests/fixtures/`.

### `uv` in `test_acceptance.py`

Acceptable, and limited to that one file. It skips cleanly when `uv` is absent
(`shutil.which("uv")`), and no other test touches `uv` — `test_plugin_discovery.py` also spawns
subprocesses but uses `sys.executable`. `uv` is used there for **cost**, not correctness: it resolves
the jax/h5py/phiflow stack from uv's cache instead of re-downloading. The thing under test — wheels
installed into a clean venv — is faithfully the end-user path.

The real observation behind the question: **no end user can run any of this suite.** `tests/` sits at
the repo root, outside `packages/*`, and no wheel includes it. The suite is a developer artifact
today. **D4** changes that for the per-package suites.

## C0 — the constraint (outranks every decision below)

The JSON structures are **not negotiable**: the graph JSON the editor exports to us, and
`node_types.json` we hand back. They are the two contracts with the DealiiX platform.

| | |
| --- | --- |
| **forbidden** | any decision that reduces coverage of either shape |
| **forbidden** | a format guard using a hand-written or specimen-authored graph instead of a real editor export |
| **forbidden** | weakening a golden from byte-comparison to content-comparison |

Measured state of the guard **before** this issue — the contract is protected only by accident:

| shape | guarded by | quality |
| --- | --- | --- |
| `node_types.json` | `test_golden_registry.py` | good — byte-for-byte per plugin |
| graph JSON | tests that *execute* graphs (up to 32.76s each), plus `TestWorkflowNodeCounts` asserting `len(nodes) > 0` | poor — the format is covered as a side effect of running simulations |

Two real editor exports — `network-from-fe.json` (33 nodes / 45 edges, the largest) and
`network-from-fe-smoke_plume.json` (24/27) — are read by **nothing except** the tests **D7** deletes.
Hence **D9**, and hence the ordering rule that governs the whole refactor:

> **A test may be deleted only once the owner of the data it reads has a suite that guards that
> data.** Concretely: the phiflow simulation tests go once `packages/coral-plugin-phiflow/tests/`
> exists and validates those three exports.

## Decisions

| # | decision | why |
| --- | --- | --- |
| **D1** | Delete `tests/fixtures/valid_nodes/`, the `registry_files` / `load_registry` fixtures, and `test_existing_registry_files_valid` | a weaker duplicate of `golden/`; its one test asserts committed data, not code. Safe under C0: these are *our* output, regenerated by us — not platform ground truth |
| **D2** | Sort tests by **owner**, not by what they import — see [The separation principle](#the-separation-principle), which is the authority for every placement question in this plan | the old suite sorted by what a test *imports*, which is an accident of how it was written. Sorting by owner is what makes the host agnostic |
| **D3** | The host suite tests against a **designed specimen** — a plain module `packages/coral-app/tests/specimen.py`, not a distribution. Zero plugin names, zero plugin markers in the host suite | `test_graph.py` and `test_nodeports.py` already do this and carry 0 markers; the four pre-#23 files carry all ~38. Not a mechanism to invent, a pattern to finish applying |
| **D4** | Each plugin carries its own tests: `tests/unit/` (itself + `coral_core`, incl. its conformance to the ABC) and `tests/system/` (+ `coral_app` as a **test-only** dependency) | completes the extension story: a third-party `coral-plugin-*` author has nowhere to put a test today. Also gives phiflow's wrappers — which have **zero** unit tests — a home |
| **D5** | Examples move to their owners: `examples/phiflow/` → phiflow package, `examples/collections/` → `coral-app`. `EXAMPLE_SPECS` deleted | the table exists only because `examples/` is divorced from the plugin that gives its graphs meaning. Once colocated, the owning directory *is* the answer |
| **D6** | A plugin hardcodes **its own** name in one constant `PLUGIN_NAME`, plus one test pinning the entry-point name. The Invariants greps are **directional** | the name is already hardcoded in the plugin's own `pyproject.toml` and is platform-facing. Deriving it from metadata would silently *follow* a rename — destroying the one assertion worth having |
| **D7** | Rule: **no unmarked test may run a simulation**; the fast lane stays ≲2s. Delete the four phiflow tautologies | 58.75s of a 59.35s suite buys four `isinstance(results, dict)` assertions. Perversely, those four are *unmarked* while `test_examples.py`'s useful phiflow case is correctly marked `slow` |
| **D8** | The remaining tautologies: 5 deleted, 2 rewritten with real assertions and rehomed to math | see [the per-test table](#d8-per-test) |
| **D9** | New guard, **in each owner's suite**: every graph the owner ships is **validated without being executed** — construct a `Graph` (all seven checks), never call `execute()` | separates *format validity* from *execution cost*, so the C0 contract is pinned at ~0ms per graph instead of up to 32.76s. It is not a central sweep: the owner already names the plugins its graphs need, so there is nothing to infer |

### Refinements from the consistency pass

| # | refinement | why |
| --- | --- | --- |
| **R1** | Split the registry golden by owner: **format + merge/ordering** → `coral-app`, generated from the specimen plugins · **content** → each plugin's own golden. **`node_types.all.json` is deleted** | today's `test_golden_registry.py` conflates the format (coral-app's) with math's surface (math's). Without the split, renaming a format key forces edits to three plugin packages before anyone can see *what* changed. Coverage is not lost but **strengthened** — see [What replaces the `all` golden](#what-replaces-the-all-golden) |
| **R2** | `test_core_contract.py` splits: the ABC's behaviour → `packages/coral-core/tests/` (+ each plugin asserting its own conformance) · the source-text greps → `tests/invariants/` | two unrelated subjects in one file. A `__future__` grep failing means *someone wrote a forbidden line*; an ABC failure means *the contract is broken* — different cause, different fix, different reader |
| **R3** | `pytest_collection_modifyitems` is **deleted**, not moved. Each plugin suite skips itself in its own `conftest.py`; nothing else needs skipping | the hook exists to skip tests that name a plugin they do not own. Under the separation principle no such test remains: the host names none, the repo-level tests name none, and a plugin's own suite is skipped wholesale by its own conftest. The markers `math` / `string` / `phiflow` go with it — a plugin's tests are now selected by **path** |

### Decided during implementation

| # | decision | why |
| --- | --- | --- |
| **D10** | **A duplicate node type fails loud.** `build_function_map` / `build_class_map` raise `coral_app.DuplicateNodeTypeError` (a `ValueError`) when a name is declared twice — by two plugins, or by a plugin and one of the host's builtins. `RivalPlugin` exists to test *that error*, not "later wins" | the merge's "later wins" was never designed: it is `dict.update()` in a loop, ratified by #16 as characterization. A graph names only the node type, so the displaced callable is invisible in the JSON — with math + string both installed, `node_types.json` silently *lost* one of the two `print_result` entries. Supersedes the silent-ignore half of #25's decision 7 |
| **D11** | `print_result` is **renamed per plugin**: math's is `print_number(value: float)`, string's is `print_text(value: str)`. Renamed consistently everywhere — both plugins, the three math exports that wire it, both characterization graphs, and the regenerated goldens | D10 is unimplementable while a real duplicate exists: the default `coral register` and `-p "math,string"` would start crashing. Naming each for what it prints also types the parameter, so graph check 6 can verify the edge feeding it (it could not, at `Any`) |

| **D12** | Each package's tests keep their collection-time constants in a **uniquely named** support module — `host_suite.py`, `math_suite.py`, `string_suite.py`, `phiflow_suite.py` — not in `conftest.py` | discovered by running the suites together. Under `--import-mode=importlib`, a test module doing `from conftest import X` goes through the normal import system, where `conftest` is a *global* module name: the four packages' conftests resolved to whichever was imported first, and three packages' tests failed to collect. pytest loads its own conftests correctly; a plain import of one does not. Paths used to parametrise over graph files are needed at collection time, so they cannot be fixtures |
| **D13** | `packages/coral-plugin-math/tests/unit/test_functions.py` imports `test_tuple_return` **under an alias** | the plugin declares a node type whose name starts with `test_`, so pytest's `python_functions = test_*` collected the plugin's own function as a test and errored on a missing fixture. The node type keeps its name (renaming one is platform-facing); only the import is renamed |

**C0 note on D11.** Three real editor exports (`network-from-fe-{functions,math,classes}.json`) had one field
edited each — the node's `type`, `print_result` → `print_number`. Recorded here because C0 rests on those
files being genuine exports: they remain byte-identical apart from that one rename, and no node, edge,
position or structure was authored by us.

## The separation principle

Sharpens **D2**. Every test belongs to exactly one of three kinds, and the directory it sits in says
which:

| # | kind | where | plugin names it may use |
| --- | --- | --- | --- |
| 1 | **host** — the app itself, on the specimen (D3) | `packages/coral-app/tests/` | **none**; never skips |
| 2 | **plugin unit** — a plugin's own functions and classes | `packages/coral-plugin-<n>/tests/unit/` | `<n>` |
| 3 | **plugin system** — that plugin's graphs run through `coral_app` | `packages/coral-plugin-<n>/tests/system/` | `<n>` |

Data ships with its owner: a graph, example or golden lives in the package whose tests use it. So a
graph's plugin requirement is its owner's name — never something a test has to work out at run time.

Repo-level `tests/` keeps only what needs **no plugin name at all**: the source-text invariants and
the wheel acceptance test. Both scan `packages/*` from disk.

**The rule that decides every case:**

> A test that needs one plugin's name belongs to that plugin. A test that needs *two* is testing a
> host rule, not a plugin fact — rewrite it on the specimen plugins and give it to the host.

That second clause is what dissolves the two awkward cross-plugin tests: the `print_result`
collision is `build_function_map`'s duplicate-name rule (`SpecimenPlugin` + `RivalPlugin`, now
asserting `DuplicateNodeTypeError` — see **D10**), and the `node_types.all.json` golden is merge +
ordering — both host rules. Each plugin's own golden (R1)
already pins its real content, so no all-plugins golden is needed.

### Who owns each data file

Read off the node types each graph uses; there is no judgement call left.

| owner | files |
| --- | --- |
| `coral-app` | `network-collections-{list,set,dict}.json`, `examples/collections/{list,set,dict}.json` — builtins and primitives only |
| `coral-plugin-math` | `network-from-fe-{math,classes,functions}.json`, `network-collections-math.json` (it uses `add`) |
| `coral-plugin-phiflow` | `network-from-fe{,-obstacle,-smoke_plume}.json`, `examples/phiflow/network-from-fe.json` |
| `coral-plugin-string` | none today |

`network-collections-math.json` is the one to notice: "collections" in the name, but it wires an
`add` node, so it is math's. The name is not the owner — the node types are.

### What replaces the `all` golden

C0 forbids reducing coverage of `node_types.json`. The `all` golden covered three things at once;
each moves to its owner and gets **stronger**, not weaker:

| what it covered | now covered by | comparison |
| --- | --- | --- |
| the file format | `coral-app`, golden from the specimen | **bytes** |
| merge + ordering across plugins | `coral-app`, from `SpecimenPlugin` + `RivalPlugin` | **bytes** |
| each plugin's node content | that plugin's own golden | **bytes** |

The `all` golden was compared by *content* (decided in #16, because cross-plugin ordering depends on
which plugins are installed). Splitting it removes that dependency — every replacement is a
byte-comparison of a fixed plugin set. This is the one place the refactor makes the C0 guard
stricter rather than merely equivalent.

```
                                         #   graphs/network-from-fe{,-obstacle,-smoke_plume}.json
```

**The owning directory replaces every hardcoded table.** A graph or example under
`packages/coral-plugin-<name>/` needs `<name>`; one under `packages/coral-app/` needs nothing. That
single rule is what lets `EXAMPLE_SPECS` be deleted (**D5**) and lets **D9** exist without any
run-time inference about which plugins a graph requires.

**Two directories, two skip policies, stated once each:**

| directory | if its plugin is uninstalled |
| --- | --- |
| `packages/coral-app/tests/`, `tests/` | nothing to skip — they name no plugin |
| `packages/coral-plugin-<n>/tests/` | the whole directory is skipped by its `conftest.py`. The directory survives `uv pip uninstall`, so it must guard itself |

**Test-space dependencies stay acyclic**: declared `plugin[test] → coral-app → coral-core` and
`plugin → coral-core`. `coral-app` needs nothing from any plugin (that is D3's whole point), and
app → plugin at runtime is dynamic entry-point resolution, not declared metadata. No packaging cycle.

## Steps

The order follows one rule, from **C0**: *a test is deleted only after the owner of the data it
reads has a suite that guards that data.* That is why the deletions come late here, rather than
second as an earlier draft had them — the guard has no home until its owner exists.

**Cost of that ordering, accepted knowingly:** the fast lane does not arrive until step 6, so steps
1–5 are developed against a ~59s suite. Work around it with `-m "not phiflow"` (~0.6s) while
iterating; do not let it tempt anyone into deleting a simulation test early.

### 1. Collection mechanics — `pytest.ini`

Prerequisite for everything: tests are about to exist outside `tests/`.

- `testpaths` covers `tests` **and** `packages/*/tests`
- `importmode = importlib` — three plugins will each have a `tests/unit/test_functions.py`
- coverage targets become explicit per package instead of `--cov=.`
- the `math` / `string` / `phiflow` markers stay for now; step 6 removes them (**R3**)

### 2. D1 — drop `fixtures/valid_nodes/`

Files, README, the two conftest fixtures, the one test. Independent of everything else.

### 3. R2 — split `test_core_contract.py`

- the ABC's behaviour → `packages/coral-core/tests/test_plugin_abc.py`;
- the source-text greps → `tests/invariants/test_source_rules.py`, gaining the directional rules:

| forbidden in | what |
| --- | --- |
| `packages/coral-app/src` | any `coral_plugin_*` import |
| `packages/coral-app/tests` | any plugin name, any plugin marker |
| `packages/coral-plugin-*/src` | any `coral_app` import |
| `packages/*/src` | `from __future__ import annotations` (existing rule) |

Allowed, deliberately: a plugin's own name inside its own tests (D6); `coral_app` inside a plugin's
`tests/system/` (D4).

The second row is the separation principle made executable — it is what stops the host suite
drifting back.

### 4. D3 + R1 — the specimen and the host suite

- write `packages/coral-app/tests/specimen.py`: the designed surface (zero-input, multi-output,
  `None`-returning, missing annotation, `Any`, a class, an *unrelated* class, a *subclass*, a dotted
  function name) plus `SpecimenPlugin` and `RivalPlugin`;
- move the four already-compliant files across unchanged;
- respecify `test_executor.py` and `test_registry.py` on the specimen — this is where the ~38 plugin
  markers disappear. `test_registry.py` also absorbs the **merge + ordering** rule, tested on the two
  specimen plugins (the `all` golden's subject, re-owned), and the **duplicate-name refusal** of
  **D10**, which is why `RivalPlugin` declares a name `SpecimenPlugin` already owns;
- **R1**: `golden/node_types.format.json`, generated from the specimen plugins, pins format and
  ordering — byte-compared;
- move `network-collections-{list,set,dict}.json` and `examples/collections/` here (**D5**'s
  coral-app half), and add `test_graphs_validate.py` (**D9**'s coral-app share);
- **verify the invariant**: `uv pip uninstall coral-plugin-{math,string,phiflow}` then
  `uv run --no-sync pytest packages/coral-app/tests` → all pass, **zero skips**. Restore with
  `uv sync`.

### 5. D4 + D6 + D5 — the plugin suites

Per plugin: `tests/conftest.py` (`PLUGIN_NAME`, and the skip that guards the whole directory),
`tests/unit/` (its functions and classes, its ABC conformance, its entry-point name),
`tests/system/` (its graphs validate **and** execute, its registry slice matches its own golden), and
`coral-app` added to a **test-only** dependency group — never `[project].dependencies`.

Rehome each plugin's graphs and examples per [Who owns each data file](#who-owns-each-data-file).
`EXAMPLE_SPECS` is deleted here: each owner tests its own.

**This step completes D9** — every editor export is now validated by its owner, which is the
precondition step 6 has been waiting for.

Phiflow gains the unit tests that do not exist today, and this is what makes deleting the four
simulation tests in step 6 a net gain rather than a trade. Verified against the source, the cheap
surface is real:

| what | cost | state today |
| --- | --- | --- |
| all five wrapper classes — `Box`, `Sphere`, `Cuboid`, `StaggeredGrid`, `CenteredGrid` construction | milliseconds, **no solver** | untested in isolation |
| the **unwrap dispatch**: `isinstance(…, PhiFlowBox)` in both grid constructors; three branches in `phiflow_iterate` (velocity, smoke, `hasattr(obstacles, "get_cuboid")`, plus `obstacles is None → ()`); `phiflow_union`'s `None`-filter and 4-way `hasattr` chain | milliseconds | covered on **exactly one path each**, as a side effect of a 7–33s simulation |
| `phiflow_union`'s `len(geometries) < 2` → `ValueError` | milliseconds | **unreachable from any graph** — check 4 requires every port wired, so the `geom2..geom6=None` defaults are dead from the graph side. Only a unit test can reach it |

What stays simulation-only, and therefore stays behind the one `slow` example: `phiflow_iterate`'s
body after unwrapping (`jit_compile`, `fluid.make_incompressible`, `iterate`) and
`phiflow_plot_and_save`'s render.

### 6. D7 + D8 + R3 — delete

Safe at last: every graph the deleted tests read is guarded by its owner (step 5).

- delete the four simulation tautologies and the rest of [the D8 table](#d8-per-test);
- `test_plugins.py` and `test_integration.py` are now empty — remove them;
- **R3**: delete `pytest_collection_modifyitems` from the root `conftest.py`, and the `math` /
  `string` / `phiflow` markers from `pytest.ini`. Nothing outside a plugin's own directory names a
  plugin any more, so nothing needs the hook.

**59.35s → ~0.6s.** The two Calculator/functions tests that D8 marks *strengthen* are not rewritten
here — step 5 already re-created them in math's `tests/system/` with real value assertions.

### 7. O1 — rehome the characterization tests

Last, and only once steps 1–6 are green. Its whole value is pinning pre-refactor behaviour, so it is
the safety net we cross on and fold up afterwards. Split: executor results → `coral-app` on the
specimen; math's numbers and stdout → math's `tests/system/`.

### 8. Documentation

- `tests/README.md` rewritten around [the separation principle](#the-separation-principle) (it
  currently describes the flat layout, and several of its sections describe files that will no longer
  exist);
- `CLAUDE.md`'s *Running Tests* section: selection is now by **path**, not by plugin marker; the D7
  rule; the directional Invariants rules; and where a new plugin's tests go — extending the *Adding a
  New Plugin* recipe with the step it is missing today.
