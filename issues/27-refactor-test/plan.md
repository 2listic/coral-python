## Answers to the audit questions

### `fixtures/` vs `golden/`

The intended distinction is **inputs vs expected outputs**: `fixtures/` is data fed *into* the code,
`golden/` is recorded output *of* the code, regenerated and compared as a regression pin.

`fixtures/valid_nodes/` breaks it. Those three files are `coral register` **output** — the same kind
of artifact as `golden/`, on the wrong side of the fence. They are read by exactly one test
(`test_registry.py::test_existing_registry_files_valid`), which asserts only that committed JSON has
the keys someone gave it: it passes with `registry.py` completely broken and fails only if a human
hand-edits a fixture. `golden/` covers the same three plugin sets properly. → **D1**.

`fixtures/valid_workflows/` is genuine input and stays (rehomed by **D5**/**D4**).

### `uv` in `test_acceptance.py`

Acceptable, and limited to that one file. It skips cleanly when `uv` is absent
(`shutil.which("uv")`), and no other test touches `uv` — `test_plugin_discovery.py` also spawns
subprocesses but uses `sys.executable`. `uv` is used there for **cost**, not correctness: it resolves
the jax/h5py/phiflow stack from uv's cache instead of re-downloading. The thing under test — wheels
installed into a clean venv — is faithfully the end-user path.

The real observation behind the question: **no end user can run any of this suite.** `tests/` sits at
the repo root, outside `packages/*`, and no wheel includes it. The suite is a developer artifact
today. **D4** changes that for the per-package suites.

## C0 — the constraint (outranks every decision below)

The JSON structures are **not negotiable**: the graph JSON the editor exports to us, and
`node_types.json` we hand back. They are the two contracts with the DealiiX platform.

| | |
| --- | --- |
| **forbidden** | any decision that reduces coverage of either shape |
| **forbidden** | a format guard using a hand-written or specimen-authored graph instead of a real editor export |
| **forbidden** | weakening a golden from byte-comparison to content-comparison |

Measured state of the guard **before** this issue — the contract is protected only by accident:

| shape | guarded by | quality |
| --- | --- | --- |
| `node_types.json` | `test_golden_registry.py` | good — byte-for-byte per plugin |
| graph JSON | tests that *execute* graphs (up to 32.76s each), plus `TestWorkflowNodeCounts` asserting `len(nodes) > 0` | poor — the format is covered as a side effect of running simulations |

Two real editor exports — `network-from-fe.json` (33 nodes / 45 edges, the largest) and
`network-from-fe-smoke_plume.json` (24/27) — are read by **nothing except** the tests **D7** deletes.
Hence **D9**, which must land *before* **D7**.

## Decisions

| # | decision | why |
| --- | --- | --- |
| **D1** | Delete `tests/fixtures/valid_nodes/`, the `registry_files` / `load_registry` fixtures, and `test_existing_registry_files_valid` | a weaker duplicate of `golden/`; its one test asserts committed data, not code. Safe under C0: these are *our* output, regenerated by us — not platform ground truth |
| **D2** | Three **kinds** of test: **Invariants** (rules about source text) · **Per-package** (one suite per distribution) · **System** (the assembled product). Admission criterion: *what is the subject of the assertion* | the old suite sorted by what a test *imports*, which is an accident of how it was written. Sorting by subject is what makes the host agnostic |
| **D3** | The host suite tests against a **designed specimen** — a plain module `packages/coral-app/tests/specimen.py`, not a distribution. Zero plugin names, zero plugin markers in the host suite | `test_graph.py` and `test_nodeports.py` already do this and carry 0 markers; the four pre-#23 files carry all ~38. Not a mechanism to invent, a pattern to finish applying |
| **D4** | Each plugin carries its own tests: `tests/unit/` (itself + `coral_core`, incl. its conformance to the ABC) and `tests/system/` (+ `coral_app` as a **test-only** dependency) | completes the extension story: a third-party `coral-plugin-*` author has nowhere to put a test today. Also gives phiflow's wrappers — which have **zero** unit tests — a home |
| **D5** | Examples move to their owners: `examples/phiflow/` → phiflow package, `examples/collections/` → `coral-app`. `EXAMPLE_SPECS` deleted | the table exists only because `examples/` is divorced from the plugin that gives its graphs meaning. Once colocated, the owning directory *is* the answer |
| **D6** | A plugin hardcodes **its own** name in one constant `PLUGIN_NAME`, plus one test pinning the entry-point name. The Invariants greps are **directional** | the name is already hardcoded in the plugin's own `pyproject.toml` and is platform-facing. Deriving it from metadata would silently *follow* a rename — destroying the one assertion worth having |
| **D7** | Rule: **no unmarked test may run a simulation**; the fast lane stays ≲2s. Delete the four phiflow tautologies | 58.75s of a 59.35s suite buys four `isinstance(results, dict)` assertions. Perversely, those four are *unmarked* while `test_examples.py`'s useful phiflow case is correctly marked `slow` |
| **D8** | The remaining tautologies: 5 deleted, 2 rewritten with real assertions and rehomed to math | see [the per-test table](#d8-per-test) |
| **D9** | New guard: every real editor export in the repo is **validated without being executed** | separates *format validity* from *execution cost*, so the C0 contract is pinned at ~0ms per graph instead of up to 32.76s |

### Refinements from the consistency pass

| # | refinement | why |
| --- | --- | --- |
| **R1** | Split the registry golden by subject: **format** → `coral-app`, generated from the specimen · **per-plugin content** → each plugin's own golden · **merge + ordering** → System | today's `test_golden_registry.py` conflates the format (coral-app's) with math's surface (math's). Without the split, renaming a format key forces edits to three plugin packages before anyone can see *what* changed |
| **R2** | `test_core_contract.py` splits: the ABC's behaviour → `packages/coral-core/tests/` (+ each plugin asserting its own conformance) · the source-text greps → `tests/invariants/` | two unrelated subjects in one file. A `__future__` grep failing means *someone wrote a forbidden line*; an ABC failure means *the contract is broken* — different cause, different fix, different reader |
| **R3** | `pytest_collection_modifyitems` moves from the root `conftest.py` into `tests/system/conftest.py` | after D3 only System has plugin markers. The invariant is restated precisely: **the host suite produces zero skips under any install subset** (plugin test *directories* do skip — the directory survives uninstalling the distribution, so each guards itself with `importorskip`) |

### One apparent rule violation, which is not one

**D6** looks like it breaks the established *"no hardcoded plugin catalog"* rule
(`conftest.py::_repo_plugin_names`, derived from `packages/coral-plugin-*`). It does not: that rule
forbids a **catalog** — one place listing which plugins exist. `PLUGIN_NAME` is a **self-reference**
inside the package that declares it, and `tests/system/` still derives the catalog from disk. Written
down here because it will look wrong to a future reader.

### D8, per test

| test | verdict | why |
| --- | --- | --- |
| `test_integration::test_classes_workflow_execution` | **strengthen** → math's `tests/system/` | has *no assertion at all*; the Calculator graph should assert `15.0` |
| `test_integration::test_functions_workflow_execution` | **strengthen** → math's `tests/system/` | same: no assertion |
| `test_integration::test_math_workflows_with_math_plugin` | delete | third re-run of the three graphs above |
| `test_integration::test_workflow_with_wrong_plugin` | delete | `try/except` over four exception types *or* success — cannot fail. Costs ~7s. Already covered precisely by `test_graph.py::test_unknown_node_type_is_rejected` at ~0ms |
| `test_integration::TestWorkflowNodeCounts` (2 tests) | delete | `len(nodes) > 0`, `len(edges) > 0` — replaced by **D9**, which validates the same files properly |
| `test_plugins::test_primitives_map_exists` | delete | `PRIMITIVES_MAP is not None`; content already asserted by `test_primitives_map_basic_types` |

| `test_registry::test_registry_file_is_valid_json` | delete | the goldens parse *and* byte-compare the same output |
| `test_plugins::TestPluginAvailability` (3 tests) | delete | asserts strictly less than `TestBuildFunctionMap` (#25 finding 3) |

`test_plugins.py` and `test_integration.py` **dissolve entirely** — every member is deleted, rehomed
or respecified.

## Target layout

```
tests/                                   # repo-level only: what no single package can own
├── invariants/
│   └── test_source_rules.py             # R2: no __future__ annotations; directional import/name greps
└── system/
    ├── conftest.py                      # R3: the plugin auto-skip hook lives HERE and only here
    ├── test_json_contract.py            # D9: every editor export validates, none executes
    ├── test_registry_all.py             # R1: cross-plugin merge + ordering; the `all` golden
    ├── test_collisions.py               # math+string both define print_result -> "later wins"
    ├── test_acceptance.py               # wheels, incremental install, cross-plugin laziness
    └── golden/node_types.all.json

packages/coral-core/tests/
└── test_plugin_abc.py                   # R2: the ABC enforces both methods

packages/coral-app/
├── examples/collections/{list,set,dict}.json          # D5
└── tests/

    ├── graphs/network-collections-*.json
    ├── test_nodeports.py                # already compliant
    ├── test_graph.py                    # already compliant
    ├── test_builtin_nodes.py            # already compliant
    ├── test_discovery.py                # already compliant
    ├── test_executor.py                 # respecified on the specimen
    ├── test_registry.py                 # respecified on the specimen
    ├── test_examples.py                 # the collections examples
    └── golden/node_types.format.json    # R1: the format, from the specimen

packages/coral-plugin-math/
├── examples/                            # if it ships any
└── tests/
    ├── conftest.py                      # D6: PLUGIN_NAME = "math"; importorskip
    ├── graphs/network-from-fe-{math,classes,functions}.json
    ├── unit/                            # math + coral_core only
    └── system/                          # + coral_app: its graphs run; its registry slice pinned
        └── golden/node_types.math.json  # R1

packages/coral-plugin-{string,phiflow}/  # same shape
    └── phiflow also takes examples/phiflow/ and
        graphs/network-from-fe{,-obstacle,-smoke_plume}.json
```

**The owning directory replaces every hardcoded table.** A graph or example under
`packages/coral-plugin-<name>/` needs `<name>`; one under `packages/coral-app/` needs nothing. That
single rule is what lets `EXAMPLE_SPECS` be deleted (**D5**) and lets **D9** derive its per-file
markers from the path instead of a catalog.

**Test-space dependencies stay acyclic**: declared `plugin[test] → coral-app → coral-core` and
`plugin → coral-core`. `coral-app` needs nothing from any plugin (that is D3's whole point), and
app → plugin at runtime is dynamic entry-point resolution, not declared metadata. No packaging cycle.

## Steps

Ordered so the cheap, risk-free wins land first and nothing removes a guard before its replacement
exists.

### 1. D9 — the JSON contract guard, `tests/system/test_json_contract.py`

Required by C0 **before** step 2. Discovers every editor-exported graph in the repo from disk, derives
the plugins it needs from its owning directory, constructs a `Graph` — which runs all seven validation
checks — and deliberately never calls `execute()`. Covers all six FE exports including the two that
step 2 would otherwise orphan. Replaces `TestWorkflowNodeCounts`.

### 2. D7 + D8 — delete and strengthen

Now safe. Deletes the four simulation tautologies and the rest of the D8 table; rewrites the two
Calculator/functions tests with real value assertions (they move to math in step 7, but get their
assertions here so nothing is untested in between). **59.35s → ~0.6s**, which makes every later step
of this refactor iterate about a hundred times faster.

### 3. D1 — drop `fixtures/valid_nodes/`

Files, README, the two conftest fixtures, the one test.

### 4. R2 + Invariants — `tests/invariants/test_source_rules.py`

Split `test_core_contract.py`. The greps stay here and gain the directional rules:

| forbidden in | what |
| --- | --- |
| `packages/coral-app/src` | any `coral_plugin_*` import |
| `packages/coral-app/tests` | any plugin name, any plugin marker |
| `packages/coral-plugin-*/src` | any `coral_app` import |
| `packages/*/src` | `from __future__ import annotations` (existing rule) |

Allowed, deliberately: a plugin's own name inside its own tests (D6); `coral_app` inside a plugin's
`tests/system/` (D4).

### 5. Collection mechanics — `pytest.ini`

Prerequisite for step 6, since tests start existing outside `tests/`.

- `testpaths` covers the repo-level dirs **and** `packages/*/tests`
- `importmode = importlib` — three plugins will each have a `tests/unit/test_functions.py`
- coverage targets become explicit per package instead of `--cov=.`
- one `slow`-lane check that `pytest -m "not slow"` still collects everything it should

### 6. D3 + R1 + R3 — the specimen and the host suite

- write `packages/coral-app/tests/specimen.py`: the designed surface (zero-input, multi-output,
  `None`-returning, missing annotation, `Any`, a class, an *unrelated* class, a *subclass*, a dotted
  function name) plus `SpecimenPlugin` and `RivalPlugin` for the collision rule;
- move the four already-compliant files across unchanged;
- respecify `test_executor.py` and `test_registry.py` on the specimen — this is where the ~38 plugin
  markers disappear;
- **R1**: `golden/node_types.format.json` generated from the specimen pins the format here; the
  cross-plugin `all` golden moves to `tests/system/`;
- **R3**: the auto-skip hook moves to `tests/system/conftest.py`;
- **verify the invariant**: `uv pip uninstall coral-plugin-{math,string,phiflow}` then
  `uv run --no-sync pytest packages/coral-app/tests` → all pass, **zero skips**. Restore with
  `uv sync`.

### 7. D4 + D6 — the plugin suites

Per plugin: `tests/conftest.py` (`PLUGIN_NAME`, `importorskip`), `tests/unit/` (its functions and
classes, its ABC conformance, its entry-point name), `tests/system/` (its graphs execute, its
registry slice matches its own golden), and `coral-app` added to a **test-only** dependency group —
never `[project].dependencies`.

Rehome the graph fixtures per the layout above.

Phiflow gains the unit tests that do not exist today, and this is what makes deleting the four
simulation tests in step 2 a net gain rather than a trade. Verified against the source, the cheap
surface is real:

| what | cost | state today |
| --- | --- | --- |
| all five wrapper classes — `Box`, `Sphere`, `Cuboid`, `StaggeredGrid`, `CenteredGrid` construction | milliseconds, **no solver** | untested in isolation |
| the **unwrap dispatch**: `isinstance(…, PhiFlowBox)` in both grid constructors; three branches in `phiflow_iterate` (velocity, smoke, `hasattr(obstacles, "get_cuboid")`, plus `obstacles is None → ()`); `phiflow_union`'s `None`-filter and 4-way `hasattr` chain | milliseconds | covered on **exactly one path each**, as a side effect of a 7–33s simulation |
| `phiflow_union`'s `len(geometries) < 2` → `ValueError` | milliseconds | **unreachable from any graph** — check 4 requires every port wired, so the `geom2..geom6=None` defaults are dead from the graph side. Only a unit test can reach it |

What stays simulation-only, and therefore stays behind the one `slow` example: `phiflow_iterate`'s
body after unwrapping (`jit_compile`, `fluid.make_incompressible`, `iterate`) and
`phiflow_plot_and_save`'s render.

### 8. D5 — examples move

`examples/phiflow/` → phiflow package, `examples/collections/` → `coral-app`. `EXAMPLE_SPECS`
deleted; each owner tests its own. `README.md` and `CLAUDE.md` documented paths updated — and stated
plainly, since `examples/` sits outside `src/` and therefore ships in no wheel (true today too): the
documented commands are **for a checkout**.

### 9. O1 — rehome the characterization tests

Last, and only once steps 1–8 are green. Split: executor results → `coral-app` on the specimen;
math's numbers and stdout → math's `tests/system/`.

### 10. Documentation

- `tests/README.md` rewritten around the three kinds of D2 (it currently describes the flat layout,
  and several of its sections describe files that will no longer exist);
- `CLAUDE.md`'s *Running Tests* section: the new invocations, the D7 rule, the directional Invariants
  rules, and where a new plugin's tests go — extending the *Adding a New Plugin* recipe with the
  step it is missing today.
